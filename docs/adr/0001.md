# ADR 0001 · Rendering: vanilla three.js, hand-written engine layer

- Status: accepted · 2026-10-15 · DEC-001

## Context

The palace is one scene with few materials but strict budgets (draw calls, triangles, bytes). A rendering layer that must hit 16.7 ms on a 2-core 2017 MacBook cannot afford framework indirection in the hot path, and the UI surface is deliberately tiny (DEC-003), so the usual payoff of a scene-graph framework does not exist here.

## Decision

Vanilla three.js with a hand-written engine layer: one scene, a hand-tuned loop, custom materials, tiny UI. Owning the small engine layer is a stronger senior signal than wiring a framework.

## Rejected alternative

React Three Fiber + drei + zustand — good for editor-like UI, but a reconciler in the hot path and 2× version coupling buy nothing for this project.

## Consequences

Frame cost is fully visible in our own code; every abstraction must justify itself. The ≤ 3 custom-materials budget is enforced by review and tests, not by a framework.
