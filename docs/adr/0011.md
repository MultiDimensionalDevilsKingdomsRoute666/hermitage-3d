# ADR 0011 · Quality tiers, boot probe and the `?q=` override

- Status: accepted · 2026-10-17, relay round 9 · DEC-011

## Context

Phase 0 shipped one render discipline: the §11 designated-device gate (no MSAA, DPR ≤ 1, drawing buffer ≤ 1 048 576 px) applied everywhere. architecture.md's tiers row promised T0/T1/T2 auto-selected at boot from a ~1 s GPU microbenchmark plus heuristics, overridable via `?q=`, persisted — machinery Phases 1–4 lean on (Playwright budget assertions, HUD, the reduce-to-T0 mobile floor). The sky-time design doc already said "the host maps existing `q` semantics to these limits rather than inventing a competing query format", so the tiering must not fork the query format or break the det contract (deterministic boots may not depend on wall-clock probes).

## Decision

- Registry in `src/engine/tier.ts`, values: T0 bounds §11 down (buffer 786 432 px, render scale ≈0.616 vs T1's ≈0.711 at 1080p), T1 sits **verbatim** on §11 (DPR 1, 1 048 576 px, 1 K shadow), T2 relaxes up (DPR ≤ 2, 4 194 304 px, 2 K shadow). `postEnabled` is `false` in all three — Phase 1 has no post stack; T2's "full post" is Phase 2 machinery, registered but not wired.
- Boot order: `?q=` override → persisted override (localStorage `zimny:tier`) → T1 in det mode (probe skipped — det boots must be composition-identical, not timing-dependent) → probe.
- The probe (main.ts wiring): ~0.85 s of rAF intervals while only the sky renders, with the renderer armed at T2 surfaces for a representative load; two warmup frames drop the slow first rAF; the **lower median** classifies (≤ 17.5 ms → T2, ≤ 30 ms → T1, else T0). The one resize happens strictly pre-arrival; the massing compiles once at the final tier (delayed `compileAsync`).
- The accepted heuristic: `navigator.deviceMemory < 4 GiB` (Chromium-only, null elsewhere) caps the tier at T0 — device facts, not inference. `hardwareConcurrency` deliberately excluded: it would misgrade the 2-core reference device.
- All changes are applied before the massing fade per §11 (no resize during fades); the shadow map is re-armed by disposal + next-pass reallocation at the tier's size.

## Rejected alternatives

- Probing at T1 surfaces — everything old and new measures ~60 fps, so the probe loses its differentiation; probing under the heaviest surfaces keeps the measurement representative.
- Mean/percentile instead of lower median — the mean drags on compile/GC hitches inside the window; the lower median is robust and needs no rounding rule beyond the documented lower-middle pick.
- `hardwareConcurrency`-based grading — 2-core reference MBP would be pushed below T1 against the roadmap's explicit goal for it.
- A runtime fps-watchdog that downgrades tiers mid-session — parked (see parking-lot): sensible eventually, but it multiplies states the golden frames must reproduce before there is any evidence it is needed.

## Open calibration item (Phase 1 exit device pass)

Thresholds 17.5/30 ms are hypotheses measured under T2 surfaces. The reference device pass records the probe's actual taste (§12 instrument + the round-10 debug HUD both show the resulting tier); if the Iris Plus 640 misgrades there, the fix is recalibrating `t1Ms` — art and tier change, the budget never does. A misgraded device that lands T0 is acceptable (floor never breaks); one that lands T2 gets reined at measurement.
